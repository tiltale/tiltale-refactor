Help

How TilTale fits together

You build the story here. Regenerate turns it into a plain website in /project/dist/ (HTML, CSS, JavaScript and one small log.php), which you upload to any web host with PHP. The start_TilTale launcher in the repository root starts this studio without a terminal, and tells you when a newer TilTale exists (updating is always your choice).

The workflow

  1. Frames are the story's screens. Create them with + Add frame, choosing a kind: a normal Frame with a background and elements (speech bubbles, buttons, images…), a Document (one zoomable image), a Validation point (invisible: sends readers on according to the global variables), or a Minigame. A frame's Fade is one setting: no fade, a crossfade, or a fade from black — both fades take Element delay seconds.
  2. Text comes from /project/content.xlsx: one row per text, one column per language. Pick a row for an element, or manage every row and the component fonts on the Content page; the images of /project/materials/ have their own Materials page (upload with the + tile, or drop files). Languages are added and renamed under Settings.
  3. Connections: set what a button does (go to a frame, end the story, or open a language). The Flowchart shows the result, and the frame editor previews the frames a frame leads to. Save and exit returns to the Develop page or flowchart, zoomed in on the frame you edited, keeping your language selection.
  4. Regenerate, then check the preview on different phones and open the Test page: a quick Play-test while building, the thorough Stress-test before publishing.
  5. Upload /project/dist/; later download dist/logs/ from the server and import it under Results. What a story records, and how to encrypt the logs with a project key (Settings → Advanced → Protect logs), is in Ethics & data.

Participants and logs

Every page load writes a new log file <participant>--<visit>.jsonl. The participant ID comes from the URL (default parameter ppn, e.g. index.html?ppn=R_abc123 from Qualtrics) or is generated. Readers who reload continue where they were; incognito windows start over. Settings → Advanced can show the first characters of the ID on final frames, so an experimenter can read back which participant a device was on.

Playing without wifi

For a classroom or field day without a connection: open <your story>/offline/ on each device while online and press Download everything. The story then opens, restarts and replays offline; every session is kept on the device and uploaded — every visit into its own log file — the next time the device is online (the same page shows what is still waiting). Old story links keep working after languages change: a retired address forwards readers to the start page.

Global variables and scoreboards

Under Settings → Advanced you can define variables such as score = 0. Any button can change one when clicked, a validation point sends readers to different frames depending on them, and any text can show one by writing {score}. The four scoreboard components are made for this and can be put on every frame at once. Every change and decision is written to the log and shown under Results.

More languages

With two or more languages, each language gets its own folder in /dist/. Optional language-picker frames (+ Add frame → Picker) form the start page /dist/index.html; their text is typed directly because no language has been chosen yet.

Keep data local

/project/ (including the generated website in /project/dist/) is ignored by Git. The full developer guide, with a table of every file, is under Docs → README, together with the license and the ethics & data notes.
